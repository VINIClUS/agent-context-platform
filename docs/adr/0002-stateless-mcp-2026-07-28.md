# ADR 0002: Stateless MCP `2026-07-28` profile

- Status: accepted
- Date: 2026-10-24
- Deciders: platform maintainers
- Code: `src/agent_context_platform/mcp/server.py`, `src/agent_context_platform/mcp/protocol_guard.py`,
  `src/agent_context_platform/mcp/auth.py`, `src/agent_context_platform/mcp/tools.py`

## Context

The platform serves its memory to Codex over MCP. The MCP specification revision
[`2026-07-28`](https://modelcontextprotocol.io/specification/2026-07-28/changelog) carries the
protocol version and client capabilities in every request's `_meta`, mirrors them into HTTP
headers on [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http),
and drops the `initialize` handshake and transport sessions
([SEP-2575](https://modelcontextprotocol.io/seps/2575-stateless-mcp)). Earlier revisions bound
state to a session (`Mcp-Session-Id`, a standalone GET stream, resumable SSE), which needs sticky
routing or shared session storage between replicas.

The API runs as more than one replica behind Cloudflare Tunnel and Cloudflare Access, with no
affinity. Every tool is read-only and answers from the ledger's projections; paging is the only
state that spans calls.

## Decision

`/mcp` implements only the stateless `2026-07-28` profile:

1. **No handshake, no session.** There is no application `initialize` or
   `notifications/initialized` handling, no `Mcp-Session-Id`, no cookie and no sticky routing. The
   SDK app runs with `stateless_http=True` (a settings field that only accepts `true`).
2. **Every request stands alone.** Each POST is validated on its own: Host and Origin, the bearer
   token (`memory:read`), POST only, the size limit, `MCP-Protocol-Version: 2026-07-28`, and the SDK's
   ladder for `params._meta`, `Mcp-Method` and `Mcp-Name`. A direct `tools/call` is valid without a
   prior `server/discover`.
3. **Discovery is optional.** `server/discover` reports the supported versions and only the
   capabilities actually served (`tools`, with `listChanged: false`).
4. **Deterministic listing.** `tools/list` is built once per process from the SDK's packaged
   schemas, sorted by name, and cached by clients for `ttlMs: 60000` with `cacheScope: private`, so
   every replica answers it byte for byte the same.
5. **Explicit handles only.** Pagination uses the composer's HMAC-signed `cursor`, bound to the
   query, the principal and the projection snapshot; any replica sharing the key can continue a
   page another one issued.
6. **Authentication per request.** A pre-provisioned bearer with the `memory:read` scope is
   verified on every request (with a short, revocation-bounded cache per replica), never derived
   from an earlier call.

The protocol details are in [the protocol profile](../mcp/protocol-profile.md); the tools in
[the tool contracts](../mcp/tool-contracts.md).

## Consequences

- Any replica can answer any request; adding or removing replicas needs no draining or affinity.
  Replicas must share `AGENT_CONTEXT_MCP__CURSOR_HMAC_KEY`, or a cursor issued by one is invalid on
  another ([deployment and scaling](../mcp/deployment-and-scaling.md)).
- Server-to-client requests, change streams and resumable streams are not available: no
  sampling, elicitation, `subscriptions/listen` or list-changed notifications. The memory tools need
  none of them.
- Clients that only speak a handshake-era revision cannot use the server; they receive a
  machine-readable rejection instead of a half-working session
  ([legacy compatibility](../mcp/legacy-compatibility.md)).
- Per-replica state is limited to caches that are safe to lose: the principal cache (bounded by
  `AGENT_CONTEXT_MCP__PRINCIPAL_CACHE_TTL_SECONDS`) and the per-principal rate-limit buckets, whose
  effective limit therefore scales with the replica count.

## Rejected alternatives

- **Sessions with sticky routing.** Keeping the handshake-era transport would tie every client to
  one replica (or need shared session storage) and make a replica restart drop sessions. It adds
  state the read-only tools never use.
- **Legacy HTTP+SSE (`2024-11-05`).** Deprecated since `2025-03-26` and classified Deprecated in
  `2026-07-28`; it needs a long-lived GET stream per client plus a separate POST endpoint, which
  conflicts with stateless replicas behind a tunnel.
- **Serving both eras.** Accepting handshake-era requests next to the stateless profile would
  double the surface to secure and test, for no client the platform supports: Codex CLI `0.147.0`
  and newer speaks `2026-07-28` (with its `mcp_2026_07_28` feature enabled where the release still
  lists it).
